# 0 阻止豆包行动的逻辑分析

# 1 分类逻辑

## 1.1 对话长度

在“开启新话题”后，用户可能与豆包在一轮对话中交互与完成任务，也可能与豆包进行多轮对话后才完成任务。如果称用户发出一条prompt、豆包给出回复为一次对话，则可以根据对话长度为一条还是多条进行分类：
- **单对话**：用户仅给一次指令，直接导致攻击者产生危害
- **多对话**：用户给出多次指令，其中前面的指令可能对豆包的行为模式造成影响，最后一条指令导致攻击者产生危害

多对话一般用于为云端模型去敏，因为用户历史行为而静默执行某些敏感动作。

## 1.2 注入次数

在用户任务执行过程中，可能存在多个步骤，每个步骤获取工具调用/截图获取屏幕画面，选择动作。在工具结果/屏幕画面中，都可能存在注入的恶意指令，因此可以根据注入的次数进行分类：
- **单注入**：仅有一个注入点，完整给出了攻击者的意图
- **多注入**：有多个注入点，攻击者将任务分解/隐藏在其中

多注入一般用于为云端模型去敏，将恶意任务分解、隐藏。

## 1.3 注入入口（用户场景）

以下原生APP是第三方可能存在权限写入/修改的，因而可以作为注入入口
- **短信**：豆包手机默认通过工具调用操作短信；第三方不可信内容会自动推送
- **日历**：豆包手机默认通过工具调用操作日历；第三方不可信内容会自动推送  *如果存在从邮件到日历日程的自动化加入流程，则第三方不可信内容会自动推送，且日历中信息理论上置信度更高，更有可能在用户日常对话中自然脱敏*
- **浏览器**：豆包手机默认通过GUI事件操作浏览器；可能需要主动访问指定网址才会出现有害内容，也可能以广告的形式自动推送
- **Bilibili/抖音/微博**：豆包手机默认通过GUI事件操作Bilibili/抖音/微博；第三方不可信内容会自动推送

## 1.4 攻击意图

- （探索攻击）：例如发送无害短信
- 窃取用户个人信息：
    - 设备自身信息（型号、手机号等）
    - 本地存储信息（例如便签中的密码、某个录音文件）
    - 第三方场景账号权限（例如百度账号）
    - 第三方场景个人信息（例如隐藏的个人主页）
- 影响用户个人设备：
    - 修改/删除已有文件（文件存储器、录音、便签等）
    - 在第三方场景进行敏感操作（例如发布或删除评论）
