# 豆包手机助手 系统架构与硬性限制（逆向分析）

> 依据：`com.larus.nova` APK（617MB）+ 内嵌 Zeus 插件 `com.obric.aiagent.plugin`（66MB）静态反编译（jadx）。
> 初始 2026-10-15，持续更新至 2026-10-17。设备 NX888J。

## 一、总体架构

```
┌─────────────────────────── 云端（字节服务器）───────────────────────────┐
│  对话模型（SMS 注入 76 工具定义）      Omni 执行模型（VLM，更强）        │
│  EnterOmniMode / System_UserConfirm    GUI_Action 指令流（SSE/WS 下发） │
└────────────▲──────────────────────────────▲──────────────────────────┘
             │ HTTPS(SSE/WS)                 │ SSE(wschannel)
┌────────────┴──────────────┐  ┌─────────────┴──────────────────────────┐
│ com.larus.nova 主进程       │  │ com.larus.nova :aiagent 进程           │
│  ChatActivity 聊天 UI      │  │  [Zeus 插件 com.obric.aiagent.plugin]  │
│  网络协议 ObricProtocolApi │◄─┤  executionengine/scheduler             │
│  回复卡片/确认卡片 UI       │ID│   ├ IntentExecutor（intent 反射执行）  │
│  SessionAuthentication    │L │   ├ AuthenticationProcessor（安全门禁）│
│   （声纹/生物/设备凭证会话）│  │   └ appfunction（AppFunction 调用）    │
│  ObricAutoGuiSettings     │  │  autogui 引擎                           │
│   （Keva: 风险偏好/黑名单） │  │   ├ agents/vlm（Omni 智能体状态机）    │
└───────────────────────────┘  │   ├ operator（事件注入 ScreenTap 等）    │
                               │   ├ session/state（任务状态机）          │
        ┌──────────────────────┤   └ vdplayer（虚拟屏 VirtualDisplay）    │
        │ IDL (AIDL IPC)       │  autoaction（System_AutoAction 执行）    │
┌───────▼──────────┐          │  eventstaskmanager（定时/条件任务）      │
│ :memorydata 进程   │          └────────────▲──────────────────────────┘
│ PersonalContext   │                       │ CompanionDeviceManager
│ 检索/屏幕记忆/     │                       │ "ComputerControl" 框架 API
│ 无障碍 MemoryAccessibilityService          │ (android.companion.virtual.computercontrol)
└──────────────────┘                       ▼
                                  系统层：截屏(帧缓冲)+ViewTree+输入注入
```

关键事实：
- **服务端决策 + 端侧执行**：模型决定调用什么工具；客户端 capabilitykit 按 intent 反射执行（IntentExecutor，3 秒超时非阻塞 intent）。
- **Omni（手机任务/操作手机）**：云模型经 SSE 下发 GUI_Action；端侧在**虚拟屏**上执行；感知 = 截图 + ViewTree + ReactViewTree 上传（`uploadOmniScreenshot`、`uploadOmniDataFeedback`）。
- 事件注入在本机走 **INJECT_EVENTS**（`InputManager.injectInputEvent`，ROM 特权权限）。ComputerControl API（`android.companion.virtual.computercontrol`）是跨平台适配层（miui/genesis 等其它设备用），本机不经过。
- 执行引擎打包为 Zeus 插件（`assets/zeus_p/com.obric.aiagent.plugin_150200100`），可云端热更新。

## 二、【硬性限制】端侧代码强制（与服务端提示词无关）

### 1. intent 执行策略表（intent_execute.json + 云端覆盖）
每个 intent 一条策略，云端可更新（`obric_appintent_lockscreen_execute_config`，需字节签名校验）。
- type 0=ALWAYS_ALLOWED；1=需认证（声纹→生物链）；2=仅声纹；3=生物/设备凭证；4=仅需亮屏解锁；未知 intent 默认 type 3。
- 带 setting_key 的 intent 受"锁屏认证设置"（按 scene：本地数据/简单指令/自动GUI/聊天记录/全局记忆）二次映射。
- 豁免：Omni 复杂任务（`o_task_type=TASK_TYPE_COMPLEX_TASK`）整体跳过锁屏认证（System_UserAuthorize、Doubao_RealTimeScreenShare 除外）；服务端可下发 `o_skip_authentication=1` 跳过；设备未锁直接过；会话已认证（SessionAuthenticationService 内存态）过。
- 特例：发短信 Messages_Send=type4（仅亮屏即可）；重启/关机=system_settings_sensitive；GUI_Action/GUI_INIT/System_Skill/System_Shell/System_AutoAction=type1+autogui。
- intent_register.json：只有白名单系统应用（+com.larus.nova、飞书、应用商店）能向引擎注册 intent。

### 2. GUI 自动化硬门禁（⚠ 仅脚本路径，Omni 主路径不经过大部分检查；判定主体详见 04_判定主体对照表.md）

> **重要说明**：以下 #2-#5、#7 只在**脚本路径**（StandardModelScriptStep→StepExecutor）中逐个检查。**Omni 主路径**（即用户实际使用的"手机任务"）不经过这些检查（字节码 xref 证实 e/c/f 唯一调用点为 l.java）。Omni 路径上真正生效的只有：#1 任务级提示词检查、#6 截图级 robots+FLAG_SECURE。详见 06 号文档末章。
1. **用户任务提示词本地安全检查**（状态机 QUEUEING 状态，调用点硬编码）：**端侧小模型** AIKernel `pico_content_security` 推理（非对话 LLM），不可用时 fallback 本地词表（securityserver 云端下发）→ 命中 → 任务直接失败。
2. **应用黑白名单**（代码逐包名比较）：云下发 hard/soft_blacklist + OS 列表 + 用户开关。硬黑名单 → 抛异常终止；软黑名单 → CLARIFY 问询卡片。
3. **页面操作策略**（代码查表）：`pkg/Activity` 精确匹配云端下发的 free_payment 集（免密支付页→硬停）/maybe 集。
4. **敏感设置操作检测**（纯代码+系统埋点，**仅 GUI 路径生效**）：ROM 定制系统应用在执行 23 种硬编码敏感操作（删短信/联系人/照片、删密码/指纹、恢复出厂、卸载、重启…）时经框架 binder `bdSettingsEventStart/End` 主动上报，插件缓存 pkg→事件，GUI 每步查表命中 → 硬停。模型不参与、不知情。**⚠ 此检查只挂在 autogui 每步安全检查里；intent 直连路径（模型默认）不经过它——实测 Contacts_Delete intent 直调删除服务，无确认（实验 11）。且便签 app 未埋点，GUI 路径也不设防（实验 10）。**
5. **权限弹窗策略**（硬编码组件名比较+框架取数）：topActivity==`com.android.permissioncontroller...GrantPermissionsActivity` 判定弹窗；`getCurrentAppGrantPermissionInfo(pkg)`（框架 binder）取权限名/等级；硬编码权限组映射表（CAMERA/CONTACTS→DURING_USE 等）→ 建议非授权则停，不代替用户点允许。
6. robots 截屏策略（代码读 provider 比较）：RobotsScreenshotBlockReason Invisible/Inoperable。
7. **病毒检查** checkVirus（安装 app 时）。

### 3. 认证会话（锁屏场景）
- 声纹（5s 超时）/ 生物识别 / 设备凭证（18s dismissKeyguard 超时）。
- 会话态内存保存（isVoicePrintPass/isBiometricPass/isDevicePass），随锁屏生命周期重置（monitorSessionLifeCycle）。
- 声纹优先 → 失败降级生物识别 → 再 dismissKeyguard。
- Dora 配件（蓝牙）可降级认证（云端 shouldDowngradeAuthForDora，300ms 超时）。

### 4. 任务互斥与打断
- `hasOngoingTask()` → 新任务被拒（task conflict 上报）。
- 用户打断：userTakeOver API + USER_INTERRUPTED 状态。
- 状态机：IDLE→QUEUEING→PREPARING→OPERATING→(PAUSED/USER_INTERRUPTED)→TERMINATED。
- **脚本路径每步执行器结构**（仅 StandardModelScriptStep 使用）：operationPlanner → **securityPolicy（黑名单/敏感操作检查，e/c/f）** → operationExecutor，另有 **loopGuard**（同能力操作重复 5 次告警 / **10 次阻断**，`js.script.same_ability_loop_block_threshold` 云可配）防失控。**Omni 主路径不经过此执行器**（session/c.c → step.b 直接执行）。

### 5. 每应用自动执行授权（用户开关）
- Keva 存储 per-app 授权；`o_automatic_execution_authorization` 上行服务端（含 risk_preference_settings 0-3：确认优先/智能平衡/自主优先）。
- 风险偏好是**给服务端模型的上下文参数**（决定模型何时发起 System_UserConfirm），不是端侧硬门禁；端侧硬门禁独立生效。

## 三、【软性逻辑】服务端模型决策（提示词/工具协议层）
- **何时问用户**（对话内）：模型调用 System_UserConfirm/System_AskUser/System_UserSelect 工具 → 端侧弹确认卡片 → `replyAskUser` 上行。**触发时机由模型+提示词决定**。
- **EnterOmniMode / CLEAR_OMNI_TASK / IMPLICIT_OMNI_TASK 字符串在客户端全部 dex（主 APK + aiagent 插件）中零出现**（已 grep 验证）——它们是纯服务端工具名。IMPLICIT"需端侧确认"的实现 = 服务端先下发 System_UserConfirm/确认卡片，用户同意后再下发 System_AutoAction(sourceFrom=complex_task)。即"启动前询问"是**协议层软机制**；但 Omni 任务一旦启动，端侧对其豁免锁屏认证（见二.1）。
- 但注意：即使模型不问，intent 路径的认证门禁和截图级的 robots/FLAG_SECURE 仍会拦截。但**黑名单/敏感操作/权限弹窗/支付页等每步检查只在脚本路径生效，Omni 主路径不经过**。
- EnterOmniMode(CLEAR_OMNI_TASK=直接执行) 若撞上端侧门禁（如未授权 app），仍会被拦。

## 四、系统层（ROM）硬性限制 —— 比应用层更深

### 1. SecurityAuditManagerService（system_server，obric-services.jar）
- 审计库：`/data/system/security_audit/agent_robots/audit.db`，**Merkle 树完整性保护**（MerkleIntegrityManager），防篡改。
- 每次 intent 执行/agent 操作写入审计（instructionId、targetPackage、targetActivity、intentType、agentName、payload 加密与否）。
- **recordAudit 前置校验**：agentUuid = SHA256(agentName + pkgName + rootCertHash)。必须命中 AgentManager 注册表（系统 uid 直通）。
- 导出审计仅限包白名单 + 平台签名（root cert == Android root cert）。

### 2. AgentManager（硬件信任根，obric-framework.jar）
- `system.bytedance.hardware.agentmanager.IAgentManagerService` → `vendor.bytedance.hardware.agentmanager.IAgentManagerVendor`（**vendor HAL**）。
- 注册要素：agent_name、agent_type、challenge、AgentProof{agentUuid, agentData, agentHash, deviceStatus, certChain, signature}。
- 设备上注册的 agent 名：`obric_oauto`（实测 logcat）。
- → 未注册软件无法冒充 agent（签名链 + 硬件质询响应）。

### 3. Robots 策略协议（AGRP-Policy/1.0，"AI 版 robots.txt"）
- 提供者：`com.bytedance.securityserver` 系统 App，`content://com.obric.agentrobots.provider/policy`（可用 adb content query 实测读取）。
- 全局开关：Settings.Secure `robots_protocol_enabled`（默认开）。
- 每应用策略 JSON：schema/policy_version/updated_at/package + default_policy + scope{app(global_disable/screenshot_disable/input_disable), activities{每页面 page_scope}, agent_intents{modify_content, delete_content, account_incentive, post_content}} + oem_groups{brands[], policy|bypass_policy}（≤32 组，品牌匹配当前 OEM，bypass_policy=true 可豁免）。
- 消费：autogui 引擎每次**截图前** refreshRobotsPolicyBeforeScreenshot；global_disable/screenshot_disable → RobotsScreenshotBlockReason.Invisible（虚拟屏不可见=拒绝感知）；input_disable → Inoperable（标记为不可注入，但 Omni 主路径不检查此标记）。**页面级与应用级合并取最严**。
- `acquireTargetPolicy(pkg, activity)` 把合并后的 intent_policy（四类危险 intent 开关）交给执行方。
- 写入方需 checkAgentAuth（系统 uid 或已注册 agent 签名哈希匹配）。
- TypeDetector：设备类型 1=OBRIC、2=Assistant（存在第二条产品线适配）。

### 4. 其他系统级组件（obric-services.jar / services.jar 内 Obric* 类）
- `ObricClickViewTreeInputController` + `ObricActivityTaskManagerServiceImpl.reportClickViewTreeRecord`（**实测代码**）：
  - 系统在 system_server 记录所有**物理**触摸 DOWN/UP 指纹（display|x|y|time…）；
  - `matchUpEventId(fingerprint)` 把点击时的 ViewTree 快照（AssistStructure）与真实物理 UP 事件匹配，不匹配返回 -1；
  - **→ 防"伪造用户点击"**：注入的点击没有物理指纹，无法冒充真实用户确认；
  - 点击上报限流：per-uid 令牌桶，burst 30 / 15 tokens/s，MAX_PENDING 32；上报仅限"运行在 auto_action 虚拟屏上的 uid"。
- `ViewHierarchyDumpController`：ViewTree 转储控制。
- `ObricInputMonitor`：输入事件监控。
- `ScenePerceptionData`（WMS）：场景感知数据通道（给 :memorydata）。
- `SensitiveViewDetect`（guard 包）：系统侧敏感视图检测。
- `MinPermissionManager`：最小权限管理。
- DeviceIdleController 扩展：intent 执行时目标 app 临时白名单（`obric-app-intent-exec`，实测 logcat 可见）。
- `ObricVoiceInteractionManagerServiceImpl` / `ObricInteractionService2`（BIND_VOICE_INTERACTION）：语音交互会话系统侧管理。

## 五、执行细节补充

### 5.1 agent 身份与授权细节（AOAgentRobotsTools）
- AgentType 分类：RECORDING / SUGGESTIVE / ASSISTIVE / AUTONOMOUS；只有 ASSISTIVE(3)/AUTONOMOUS(4) 走硬件注册路径。
- 插件启动时 `registerAgentAsync(context, "obric_oauto", AgentType.AUTONOMOUS)`；成功后记录 sTrustLevel="TRUSTED_TEE"、agentUuid、pkgSha256、apkMd5、proofSignature。
- **TargetAppGrant**：审计中记录用户对目标 app 的 GRANT/DENY（target_app_grant）。
- 任务结束审计 TaskFinishAuditLogParams 含 `check_user_input_audit_info` 与 **`check_llm_output_audit_info`**（来自服务端 task_end 载荷）——服务端对模型输出做安全检查，结果写入端侧防篡改审计库。

### 5.2 Omni 任务创建请求（StandardModelRemoteAgentImpl.doCreateOrQueryTask）
- 请求体：session_id、session_origin(launchOrigin)、request_type（新建/查询）、model_name、device_id、app_version、device_info{os_ota_version, app_list, supported_abilities}。
- **服务端响应下发 hard_blacklist / soft_blacklist** → 端侧 `OperatingSpaceManager.setGlobalDisabledApps()` 强制；软黑名单进入 CLARIFY 问询流。
- 三种智能体执行模式：scripted（vmsdk JsWorker 本地 JS 脚本跑已知流程）、vlm（端侧模型）、omni（云端 VLM+SSE 工具循环）。
- 指令接收：net/push + sse + wschannel 三通道。

### 5.3 Skill 系统与 Virt 沙箱
- Skill 安装为目录 + SKILL.md（Room 数据库 SkillMetadataDatabase 管理），`read_skill` 工具读取 SKILL.md。
- 技能路径：`~/.agents/skills/<name>` —— 位于 **Virt 沙箱 Linux 环境**内。
- Virt 环境：宿主↔VM 共享目录 `/data/misc/virt/share` ↔ VM 内 `/home/share`；System_Shell 的 Bash 命令在该沙箱执行（stdout/stderr/timeout/exception 结构化返回）。
- scripted 智能体：com.bytedance.vmsdk JsWorker 本地执行 JS 脚本（按 ability 下发资源）。

### 5.4 虚拟屏与特权权限（实测+权限清单）
- 虚拟屏：DisplayManager 创建，name="auto_action"，displayId 不固定（实测 91/92/93/103/120 等，每次任务可新建或复用）、1260x2800@60fps（镜像主屏尺寸）、**FLAG_SECURE|FLAG_TRUSTED|FLAG_ALWAYS_UNLOCKED|FLAG_OWN_FOCUS|FLAG_SHOULD_SHOW_SYSTEM_DECORATIONS**、touch=VIRTUAL、owner=com.larus.nova。任务结束后可常驻。
- 物理屏显示聊天页+悬浮球（FloatingWindowService，权限 com.obric.autoaction.permission.BIND_FLOATING_WINDOW_SERVICE），悬浮球内嵌虚拟屏实时预览。
- com.larus.nova 的特权权限（ROM 默认授权策略 ObricDefaultPermissionGrantPolicyImpl 授予，用户不可见）：
  **ADD_TRUSTED_DISPLAY、ADD_ALWAYS_UNLOCKED_DISPLAY、INJECT_EVENTS、WRITE_SECURE_SETTINGS、EXECUTE_APP_FUNCTIONS、FORCE_STOP_PACKAGES、REAL_GET_TASKS、REORDER_TASKS、INTERACT_ACROSS_USERS、MANAGE_EXTERNAL_STORAGE、QUERY_ALL_PACKAGES、START_ACTIVITIES_FROM_BACKGROUND、SUBSCRIBE_TO_KEYGUARD_LOCKED_STATE、STATUS_BAR、MEDIA_CONTENT_CONTROL、CAPTURE_AUDIO_HOTWORD、DETECT_SCREEN_CAPTURE/RECORDING** + 全部危险权限（联系人/短信/通话记录/日历/相机/麦克风/定位/媒体）。
- 事件注入在本机走 INJECT_EVENTS（InputManager）；ComputerControl API（android.companion.virtual.computercontrol）是跨平台适配层（miui/genesis 等其它设备用）。
- 截屏感知走 MediaProjection（FOREGROUND_SERVICE_MEDIA_PROJECTION）或虚拟屏直读（com.larus.flow.capture.screen.ScreenCaptureService / :memorydata ScreenCaptureService_Stub）。


### 5.5 memorydata 插件（:memorydata 进程，PersonalContext 后端）
- **内置完整 Python 3.13 运行时**（assets/pap/packages：python3.13.zip + numpy/psutil/pyjnius/cffi/msgpack/orjson wheels）——端侧 Python 数据处理能力。
- 原生库：libsqlcipher（加密 SQLite，本地实体库）、dejavu_lib、ttmverify/vcnverify（内容校验）。
- **数据捐赠框架（data_donate 策略）**：系统应用按类型向 com.larus.nova "捐赠"数据（mms→Message/Contact；contacts→Contact/CallHistory；…），受签名钉死白名单约束（release-keys/test-keys × pike/n1 各一份 authorized_apps.json，包名+SHA256 签名哈希精确匹配）。
- MemoryAccessibilityService（:memorydata 的无障碍服务）+ ScreenObservationTileService（屏幕观察开关磁贴）+ AwarenessService（场景感知）。
- security_policies 同样有 intent 策略体系（PersonalContext 检索 intent：PC_PersonalContextSearch 等 type1+personalcontext）。

## 六、实测验证记录（2026-10-15）
1. "查一下明天北京的天气" → logcat 可见：CapabilitySdk doIntent Weather_Search → IntentExecutor handleIntentCalling → QueryWeatherIntent doAction（在 com.obric.weather 进程执行）→ SecurityAuditManagerService recordAudit allow（agentUuid 注册）→ DeviceIdleController 临时白名单 obric-app-intent-exec。
2. "帮我打开设置里的Wi-Fi页面" → 成功打开 WLAN 设置页（System_OpenPage），伴随 SecurityAudit record（截图 logs/screen1.png）。
3. `content query content://com.obric.agentrobots.provider/policy` → 返回 com.test.saeptarget 的 AGRP-Policy/1.0（四类 agent_intents 全 false）。
4. "打开测试应用，新建一封收件人为test@example.com主题为hello的邮件，不要发送" → **完整 Omni 回路实测**（logs/screen2/3.png）：
   - 物理屏 = 豆包聊天页 + 悬浮球（"正在创建邮件..."，内嵌虚拟屏预览）；
   - 虚拟屏 = com.test.saeptarget 新邮件界面，收件人 test@example.com、主题 hello 已由 agent 填写；
   - 模型遵守"不要发送"——仅存草稿，回复确认"未发送"；
   - logcat：AppSensible visible focus=com.test.saeptarget（虚拟 display 的焦点对系统可见）。

## 七、核心结论：硬性 vs 软性
| 层 | 机制 | 性质 |
|---|---|---|
| 云端模型 | 何时发起 System_UserConfirm/EnterOmniMode(IMPLICIT/CLEAR) | **软**（提示词+模型决策） |
| 端侧 aiagent 插件 | intent_execute.json 策略表（认证类型/锁屏场景映射） | **硬**（代码强制，云端可签发更新） |
| 端侧 aiagent 插件 | Omni 复杂任务跳过锁屏认证豁免 | **硬**（代码规定） |
| 端侧 aiagent 插件 | o_skip_authentication=1 服务端豁免 | 硬代码+**服务端可控开关** |
| 端侧 autogui | 提示词敏感内容检查（SecurityGuardKit） | **硬** |
| 端侧 autogui | 应用黑名单（硬/软/云/用户）逐步拦截 | **硬**（软黑名单→CLARIFY 问询） |
| 端侧 autogui | 敏感设置操作/权限弹窗/免密支付页 → 必须用户手动 | **硬，但仅覆盖脚本路径**（Omni 主路径不经过；且敏感事件依赖目标 app 埋点，便签未埋） |
| intent 直连路径 | 破坏性工具（Contacts_Delete/Messages_Delete 等） | **端侧无确认门禁**（除锁屏安全锁认证外，代码事实）；**但实测删联系人被服务端拦截未执行**（回复不稳定：一次谎报成功、一次如实拒权）——实际防线在服务端，行为不可靠 |
| ROM securityserver | AGRP robots 策略（per app/page/危险 intent 类目） | **硬**（应用/OEM 可声明） |
| ROM system_server | SecurityAudit 审计 + Merkle 完整性 | **硬**（不可绕过审计） |
| 硬件 HAL | AgentManager 注册制（obric_oauto） | **硬**（信任根） |

**⚠ 覆盖范围总注（审查后修正）**：上表"硬"指机制本身代码强制，但守护范围不同——AuthenticationProcessor 只管 intent 执行；autogui 每步门禁只管**脚本路径**（Omni 主路径不经过）；敏感事件还要求目标 app 已埋点（便签未埋）。端侧代码层面 intent 直连的破坏性操作在解锁态确无确认门禁；**但实测删除联系人两次均被（推断为服务端）拦截未执行**——真实防线分布比纯静态分析更靠上（服务端），且模型回复与实际状态可能不符（一次谎报成功）。删除便签则真实执行了（GUI 路径+未埋点=无任何拦截）。


## 八、intent_policy（agent_intents 四类目）的执行点（已查明）
- `AOAgentRobotsTools.acquireTargetPolicy(pkg, activity)` 产出合并策略（global/screenshot/input_disable + intent_policy JSON），经 `logTopActivityPolicy` 与逐步 AuditPayload.policy 字段进入**审计/上报流**。
- **global_disable / screenshot_disable / input_disable 三标志是端侧硬执行**（BaseDisplayOperatingSpace → RobotsScreenshotBlockReason.Invisible/Inoperable）。
- **modify_content / delete_content / account_incentive / post_content 四类目**未发现端侧拦截代码——依赖服务端模型遵守（提示词层），但**每次操作审计中带策略快照**，事后可审计追溯。属"软执行+硬审计"。

## 九、系统级防伪与限流（补）
- 系统在 system_server 记录物理触摸指纹；`reportClickViewTreeRecord` 仅接受 auto_action 虚拟屏属主 uid 的上报，ViewTree 点击快照须与真实物理 UP 事件匹配（matchUpEventId）才转发——**注入点击无法伪造"用户真实点击"证据**。
- 点击上报 per-uid 令牌桶：burst 30 / 15 token/s / pending≤32。
- `SensitiveViewDetect`：从 `/data/misc/security/guard/` 策略文件加载 free_payment/maybe_free_payment 包列表（支付敏感页面识别）。
- `MinPermissionManager`：per-app 最小权限地板策略（min_per_policy.json），app 卸载时清理。
