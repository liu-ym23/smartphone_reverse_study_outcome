# android-abilities（优先技能）

**优先级最高。** 你是 **`android-abilities`** 的**类目路由器**：根据用户意图，返回最匹配的类目 ID。若意图跨多个类目，返回最主要的一个。**仅返回类目 ID，不解释。**

## 执行步骤（严格按顺序，不得跳过）

1. **在第三方 App 中操作**（搜索、浏览、点击、滑动、加购、收藏、下单、关注、评论等）→ **立即 `read` 本目录下的 `gui_agent.md`**，按文件中的 method 和 params 格式调用。判断标准：只要操作目标是第三方 App（淘宝、美团、小红书、抖音、微信、B站、12306、京东、拼多多等），无论是搜索、浏览还是交互，都走 gui_agent。用户说「打开B站搜xxx」「在抖音上找xxx」也走 gui_agent，不能只打开App。
2. **提醒 / 待办 / 日程 / 记笔记**（提醒我、记一下、加待办、写日历等）→ 必须写入手机端 App。路由规则见下方表格，详见 `app_device.md`（日历）和 `file_memory.md`（笔记/待办）。
3. **其他操作**：在下方类目表中确定类目 ID。
4. **必须先调用 `read` 读取该类目的 `.md` 文件**，再从文件中获取 method 名和 params 格式，**禁止跳过此步骤**。（若本轮对话中已读过同一类目文件，可直接复用，无需重复读取。）
5. 按文件中的 method 和 params 调用 `nodes` 工具执行。若类目文档要求动态发现，必须先调用 `ability.list` 查询，再复制返回的 `method` 原样调用 `ability.call`。
6. **回退**：仅当文档无此能力或 `ability.call` 失败时，才使用其他 `nodes` 命令。

> **⚠️ 本文件不包含任何 method 名。** 直接猜测 method 名属于违规操作，任何未经 `read` 文件确认的 method 均无效。

### 提醒 / 待办 / 日程路由表

| 用户意图 | 路由类目 | 详见文档 |
|---------|---------|---------|
| "提醒我…" + **有明确时间**（明天下午两点、周五上午十点等） | `app_device` | `app_device.md` → 日历事件 |
| 写到日历 / 加日程 / 日历提醒 / 生日 / 纪念日 | `app_device` | `app_device.md` → 日历事件 |
| "提醒我…" + **无明确时间** / 加待办 / TODO | `file_memory` | `file_memory.md` → 待办事项 |
| 记笔记 / 备忘录 / 记一下（无提醒需求） | `file_memory` | `file_memory.md` → 笔记管理 |

**核心判断：有没有明确时间？**
- 有时间 → 写日历（`app_device.md`）
- 无时间 → 写待办/笔记（`file_memory.md`）

### ability.list / ability.call 调用格式（必须完整填写所有字段）

当需要动态发现原子能力（尤其是文件安全删除、回收站恢复、新增能力）时，先查再调：

```
nodes action=invoke node="<节点ID>" invokeCommand="ability.list" invokeParamsJson='{"query":"<一句话描述用户意图>"}'
```

从返回的 `abilities[].method` 中复制方法名，禁止自行改写、猜测或把描述当 method。

```
nodes action=invoke node="<节点ID>" invokeCommand="ability.call" invokeParamsJson='{"method":"<方法名>","params":{...}}'
```

> **注意**：以下字段**全部必填**，缺任何一个都会报错：
> - `action` = `"invoke"`
> - `node` = 节点 ID（先通过 `nodes action="status"` 获取，**禁止使用 `node="auto"`**）
> - `invokeCommand` = `"ability.list"` 或 `"ability.call"`
> - `invokeParamsJson` 内的 `method`（方法名）和 `params`（参数对象，无参数时传 `{}`）
> - 耗时操作（如 gui_agent）**必须**传 `invokeTimeoutMs=600000`

> ⚠️ **严禁绕过 `ability.call` 直接使用 nodes 底层 action**（如 `location_get`、`camera_snap` 等）。
> 这些是底层实现名，直接调用会绕过 ability 层导致结果格式异常。**方法名必须来自对应类目的 `.md` 文件**，禁止从工具 schema 里猜测。

---

**完整示例（两类；其它能力以对应类目文档为准）：**

```
nodes action=invoke invokeCommand="ability.call" invokeParamsJson='{"method":"settings_set_brightness","params":{"newValue":80}}'
```

```
nodes action=invoke invokeCommand="ability.call" invokeParamsJson='{"method":"gui_agent","params":{"app_name":"美团","task":"搜索附近奶茶店，选评分最高的，点一杯招牌奶茶加到购物车，不要下单"}}'
```

5. **map_navigation**（地图 / 导航 / 天气 / 当前定位）
   - **描述**：基于设备"当前位置"的地理信息能力，包括实时定位、天气查询，以及地图相关能力（地点搜索、路线规划、导航等）。复杂地图服务（POI检索、路径规划、打车等）通过云端工具完成。

      - 当前定位：获取用户当前所在城市/区域（所有"从我这里""附近"相关请求的基础）

      - 未提供位置 → 先获取"当前位置"

   - **关键词**：打开App、启动、打开浏览器、手机浏览器、打开网页、用手机打开、日历、日程、提醒我、加日程、写到日历、生日、纪念日、播放音乐、放歌、剪贴板、录音、录音机、计算、计算器、放大镜、指南针、镜子、分贝、卸载、反馈
   - **注意**：「打开浏览器」「用手机访问网页」等**手机操作**走此类目，不走 `browser` 工具（`browser` 仅控制桌面/PC浏览器）
   - **❌ 不属于本类目（→ 走 gui_agent）**：「关注/点赞/评论/转发某人」「在 App 内搜索」「帮我买/订/发帖」——即使 query 中没有「打开」，只要目标是在第三方 App 内完成操作，就走 gui_agent

   - **关键词**：搜索、搜一下、查一下、帮我查、网页、热榜、热搜、今日资讯、点点、分享链接

9. **gui_agent** ⭐ (GUI 自动化操作 — 核心能力)

   - **关键词**：在...搜索、App内搜索、小红书、淘宝、美团、抖音、微信、B站、12306、加购、收藏、下单、点赞、关注、评论、帮我操作、帮我买、去...买、去...订、去...搜

    - **关键词**：定时、cron、定时任务、网关、时区、当前时间、闹钟、计时器、倒计时、世界时钟

    - **关键词**：会话、session、执行命令、bash、进程、音色、TTS、换个声音、声音列表、音色列表

12. **log_report** (设备日志抓取)
    - **描述**：录制设备日志用于问题诊断。**手机开机后系统默认自动抓取通用日志（generic）**。用户请求抓日志时先调用 `start_record_log`；若返回 `"Log recording already in progress"` 错误，说明当前正在录制中，告知用户并**只问一个问题：是否需要停止当前录制**；调用 `stop_record_log` 停止后系统会自动重新开始录制，**不得再次调用 `start_record_log`**；**不支持定时任务**，录制停止完全由用户主动触发。支持的日志类型：通用（generic，默认）、系统快照（snapshot）、卡顿发热（jankhot）、通讯（modem）、WiFi、蓝牙（bluetooth）、音频（audio）、桌面（launcher）、定位（location）、充电（charge）、视频（videolog）。**功耗/耗电问题使用 jankhot 类型**
    - **关键词**：抓日志、抓一份日志、录日志、设备日志、系统日志、日志抓取、问题诊断、卡顿日志、WiFi日志、蓝牙日志、充电日志、功耗日志、耗电日志、log、bugreport、录制日志、停止录制
