## 已确认事实

### 1. 风险偏好（RiskPreferenceSettings）
- 注解 `com.obric.assistant.RiskPreferenceSettings`：`NONE="0"`, `CONFIRM_FIRST="1"`, `SMART_BALANCE="2"`, `AUTONOMY_FIRST="3"`。
- 存储：Keva key `risk_preference_settings`（repo `obric_settings_<uid>`），默认 `"2"`，**未登录强制返回 "2"**（ObricSettingsServiceImpl.O()）。
- 设置 UI：`ObricRiskPreferenceViewModel`（确认优先/智能平衡/自主优先）。
- 出口：`getAutoExecuteAuthorizationStatusMap()` 打包为 `o_automatic_execution_authorization`（含 risk_preference_settings + 云控 `auto_gui_automatic_execution_authorization` 的 authorizations 数组），经 `FlowSettingsIDL` IPC 提供给 flow 进程 → 上行服务端。
- 埋点 key：`omni_risk_preference_setting`（ObricLaunchReportManager）。同组还有 `omni_app_custom_permission`、`omni_system_settings_modification`、`omni_install_app`（安装应用/改系统设置/应用自定义权限的独立授权）。

### 2. 询问用户的机制（System_UserConfirm / AskUser）
- `capabilitykit` 有 `System_UserConfirm` intent（params: candidates[] + confirmIntent）和 `System_AskUser`；还有 `System_UserSelect` / `System_MultiUserSelect`（eda/b.java 卡片抑制逻辑中按 intentName→页面集合过滤）。
- 网络协议：`replyAskUser(askContent, userAnswer, extra)`（ObricProtocolApi）——模型问→用户答→上行。
- 确认卡片 UI：`UsrConfirmEntityCard` / `UserConfirmEntityCell`。
- **待确认：谁触发 System_UserConfirm（服务端模型决策 vs 客户端硬规则）**

### 3. Omni（操作手机）执行回路
- `uploadOmniScreenshot(toolId, imageCount, imagePath, mime, source, ...)`、`uploadOmniDataFeedback(viewTreePath, reactViewTreePath, ...)` — 截图 + ViewTree + React ViewTree 上传。
- 任务控制 API：`userTakeOver`、`operateQueue`、`additionTask`、`clearAllOmniTasks`、`notifyStopComplexTask`、`getOmniModelConfig`、`getOperationInstructions`。
- IFlowSettingsIDL 授权面：`getAutoExecuteAuthorizationStatusMap`、`getAutoGuiEnabledScene`、`getAutoGuiFastModeUseSettings`、`getIntentAuthStatus(settingKey)`、`getOAutoUseClipboardEnabled`、`getOUseMemoryEnabled`、`isVoicePrintAuthenticateAutoGuiEnabled`（声纹验证）、`isLarkSendConfirmEnabled`（飞书发送确认）、`getAutoImageUploadEnabled`、`getAuthenticationTypeOnLockScreen(scene)`。

### 4. 应用黑白名单（自动执行范围）
- `ObricAutoGuiSettingsImpl`：云控软黑名单（getAppSoftBlacklistFromCloud）+ OS 黑名单 + 用户黑名单合并；`getAutoActionA16UserAvailableApps`、`getAvailableAppPackageNamesFromCloudAndOs`。
- SAEP 受限包读取：`ObricSaepRestrictedPackageReader`。

### 5. 安全相关
- `com.obric.assistant.ipc.BypassAdaptiveSidPusher` + 日志 "checkSecurityPolicy bypass conversation security, type="、"runAuthAndDispatch skip: bypass adaptive sid"（settings key `obric_bypass_adaptive_sid`）。
- 设置项 `System_PresentSettingEntry(setting_type=operation_authorization)` 展示"操作授权模式/bypass 模式"入口（工具定义原文）。

### 6. 【核心】intent 执行安全策略（硬规则引擎）
位置：`com.larus.nova` APK 内打包的 Zeus 插件 `assets/zeus_p/com.obric.aiagent.plugin_150200100`（66MB，完整执行引擎）。
- 策略文件：插件内 `assets/security_policies/intent_register.json`（应用→可注册 intent 白名单）+ `intent_execute.json`（每个 intent 的执行策略）。
- 加载器：`executionengine/scheduler/impl/execution/security/b.java`（PolicyLoader）：**优先云端** `getObricCloudConfig("obric_appintent_lockscreen_execute_config")`（RSA/ECDSA 签名校验，只认字节签名），失败回退 assets 内置版本。策略可被云端远程更新。
- 执行检查：`security/a.java`（AuthenticationProcessor）。**所有 intent 执行（execIntentAsync）与 AppFunction 执行前强制经过**；非 IntentParams 类型豁免（实际全部业务 intent 都是 IntentParams）。
- **policy type 语义（已解码）**：
  - `0` = ALWAYS_ALLOWED（直接放行）
  - `1` = REQUIRES_AUTHENTICATION（声纹→生物识别链）
  - `2` = REQUIRES_ONLY_VOICEPRINT_AUTHENTICATION（仅声纹）
  - `3` = REQUIRES_NOT_VOICEPRINT_AUTHENTICATION（生物识别/设备凭证；GENESIS_R/M + Notes_Create + 锁屏时强制解锁）
  - `4` = REQUIRES_SCREEN_UNLOCK（仅需亮屏解锁，不需身份验证）
  - `99`/其他 = 拒绝（认证错误）
- **effective type 计算**：JSON 里带 setting_key 的 intent，type 会被"锁屏认证设置"覆盖（`getAuthenticationTypeOnLockScreen(scene)`，scene 由 setting_key 映射：contacts/phone/messages/notes/office→LOCAL_APP_DATA_ACCESS，autogui→AUTO_GUI_EXECUTE，camera/system_settings/audio_control/clock_simple/weather→SIMPLE_COMMAND_EXECUTE，memory→GLOBAL_MEMORY_ACCESS，chat/history→CHAT_*...）。设置返回值 0→type3（生物识别）、1→type1/2（声纹）、2→type0（放行）、3→99（拒绝）。
- **统一豁免条件**（processRequiresAuthentication 系列）：
  1. `o_task_type == TASK_TYPE_COMPLEX_TASK` 或 `long_task_state == "main"`（**Omni 复杂任务整体跳过锁屏认证**；System_UserAuthorize 和 Doubao_RealTimeScreenShare 除外）
  2. `ext["o_skip_authentication"] == "1"`（**服务端可下发跳过认证标记**）
  3. 设备未锁（isDeviceLocked == false）
  4. 会话已认证（`IAgentAuthService.isAuthPass(intentName, messageId)`）
- 未知 intent（策略表无条目）→ 默认 type 3（最严格之一：需生物识别）。
- intent_register.json 白名单外的 app 不能向引擎注册 intent（subject 白名单：系统应用 + com.larus.nova 自身 + 飞书 + 应用商店等）。
- per-app License 覆盖：`LicenseExecutePolicyInfo`（`authentication/license/a`）可按包名覆盖策略（安装应用 license？）。
- Dora（蓝牙配件）可降级认证（`shouldDowngradeAuthForDora`，300ms 超时）。
- 特例：`Messages_Send` type=4（只需解锁屏幕）；`Phone_Call` type=0+phone（仅锁屏设置约束）；`System_Reboot/Shutdown/SwitchNotification` → system_settings_sensitive；`GUI_Action/GUI_INIT/System_AutoAction/System_Skill/System_Shell` → type1+autogui；`System_OpenApp` type4（相机子动作例外）。
